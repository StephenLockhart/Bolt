快慢机（工作代号）· 产品需求文档

1 背景与目标

1.1 问题与依据

当前 AI 应用几乎都工作在"短思考"模式：一个会话、一次问答、人盯着屏幕等结果。人一走开，思考就停；任务一长，会话就断。而人的注意力是有限的，不可能陪着 AI 跑完一个持续几天的任务。

这一判断有两类外部依据：

  • 注意力是稀缺资源。Anthropic 在《Effective context engineering for AI agents》（2025-09-29）中指出 LLM 存在"注意力预算"（attention budget），上下文是边际收益递减的有限资源，并给出长时程任务的三类手法：压缩（compaction）、笔记沉淀（note-taking）、用子代理隔离预算。人侧同理：用户能分配给"监工 AI"的注意力是固定额度。来源：anthropic.com/engineering/effective-context-engineering-for-ai-agents
  • 行业正在走向后台长跑，但只解决了一半。OpenAI《Introducing Workspace Agents in ChatGPT》（2026-04-22）描述的云端 Agent 可在用户离线时持续处理"复杂的任务和长期运行的工作流"，必要时请求人工审批。来源：openai.com。但它们仍把"与人对话"和"长期推进"视为同一种工作模式，缺少两种节奏之间的切换、交接与回流机制。

命名依据：认知科学的双系统理论（Kahneman《思考，快与慢》，System 1 / System 2）。"快慢机"借用枪械射速选择器的隐喻：同一个执行体，切换两种节奏档位。

1.2 产品决策

契约项定义
主要用户在宿主环境（codex 或 dsh）中使用 AI 对话推进工作的个人用户 [Assumption, TBD：人群定义待访谈确认]。
核心工作把自己的长期工作（调研、企划、开发等）交给 AI 持续推进，同时保住自己的注意力。
触发快挡对话中产生一个需要多日推进的需求，用户确认转交慢挡。
完成条件长思考任务的成果满足简报中的完成定义并经用户确认，状态转"已完成"。
共享业务对象长思考任务（见 3.2），快挡创建与干预，慢挡推进与交付。
信任边界执行体永不自行修改目标、不自行宣布完成、不外发成果；人保留全部关键决定权（见 5.6）。

产品把 AI 的思考明确拆成两条轨道，用一套交接协议连接它们：

  • 快挡（短思考）：与人实时对话的轨道。负责听需求、澄清问题、确认决策、回答追问。特点是快、浅、随叫随到，占用的是人的注意力。
  • 慢挡（长思考）：后台推进任务的轨道。负责一个长期任务的持续推理与执行，跨多个日历日、断断续续运行，不要求人在线。特点是慢、深、可中断可恢复。

两轨之间只交换两种标准产物：简报（快→慢，人的意图）与进展摘要（慢→快，机器的进度）。人只在需要决策时被打扰。

1.3 目标（可观察结果）

  • 用户在快挡对话里完成一次简短确认，即可把一个长期任务交给慢挡，不需要离开当前工作面。
  • 长思考任务可跨多个日历日推进，期间用户关闭会话、关机离线，任务进度不丢失。
  • 用户回到快挡时，一屏之内能看到全部长任务的状态，以及明确列出的"需要你决策"的事项。
  • 任何长思考任务中断后可从最近快照继续，目标定义与已完成工作不丢失。
  • 用户注意力只被两类事件打断：需要人决策、成果待确认；其余进展静默更新在任务面板里。

2 范围

2.1 最小完整旅程（P0）

环节定义
入口条件用户在宿主环境（codex 或 dsh [TBD：宿主所指待确认]）中打开快挡会话，且已存在至少一个可讨论的需求。
P0 行为① 快挡对话讨论需求 → ② 生成简报并经用户确认 → ③ 创建长思考任务，慢挡在后台断续推进 → ④ 任务遇到需人决策的节点时回流快挡 → ⑤ 用户答复后慢挡继续 → ⑥ 提交成果，用户确认完成。
完成证据任务状态变为"已完成"，成果物可见、可取用；工作段记录与进展摘要完整留痕。
恢复路径任何时刻宿主进程关闭、执行中断、运行失败，任务停留在最近快照，用户可从任务面板重试或继续，不需要重新描述需求。

2.2 P1（后续版本）

  • 多任务之间的依赖与编排（任务 A 的产出是任务 B 的输入）。
  • 定时 / 事件唤醒的调度策略（定期巡检类任务）。
  • 团队共享长思考任务、多人审批与权限分级。
  • 成本配额、消耗统计与超限预警。
  • 多宿主适配（同一任务可在不同宿主中查看与干预）。
  • 成果版本对比与回滚。

2.3 明确排除（P0 不做）

  • 多人协作、组织级权限与审计合规。
  • 计费、订阅、配额商业化。
  • 把成果自动发布到外部系统（仓库、文档站等）。
  • 独立图形客户端；P0 的工作面就是宿主的对话界面。

3 产品模型

3.1 双轨思考模型

快挡短思考 · 陪人

  • 节奏：秒级响应，会话内连续。
  • 对象：人的一次注意力窗口。
  • 职责：需求澄清、简报生成、决策确认、追问解释。
  • 结束条件：人离开即结束，不留待办。
  • 上下文：只保留当前会话与全部长任务的摘要视图，不装载任务内部细节。

慢挡长思考 · 伺候任务

  • 节奏：工作段制，跨天、断断续续。
  • 对象：一个长思考任务的完整生命周期。
  • 职责：持续推理、拆解执行、沉淀状态、产出成果。
  • 结束条件：成果被确认，或被取消/失败。
  • 上下文：每段推进前从快照恢复，段内可压缩，但简报与完成定义永不丢弃。

3.2 核心对象：长思考任务

快慢两轨共享的唯一业务对象是"长思考任务"。快挡创建它，慢挡推进它，双方围绕它协作。字段定义如下：

字段类型必填规则
任务 ID文本系统生成创建时生成，唯一且不可修改。
名称文本是取自简报，默认取简报目标的首句摘要，用户可改。
目标与完成定义长文本是简报核心；慢挡以此判定工作是否收敛；修改走 5.5 目标变更规则。
约束与边界长文本否不允许做的事、时间要求、参考范围。
背景资料引用列表否快挡会话中产生的相关文件、链接、结论。
状态枚举是见 5.1 状态机，同一时刻只有一个状态。
当前进展摘要长文本是（创建后）慢挡每个工作段结束时更新，面向人的语言。
下一步计划长文本是（创建后）同上，说明下一工作段打算做什么。
工作段记录记录列表否每段一条：起止时间、动作、产出、关联快照。
最新快照指针是（首个工作段后）指向最近一次落盘的完整状态，见 5.4。
待决策事项列表否慢挡提请人决策的问题及选项，是快挡唯一默认推送的内容。
成果物引用列表否完成时提交的产出。
创建时间 / 最近更新时间时间戳是系统维护。

3.3 交接协议

交接产物方向内容触发
简报快挡 → 慢挡目标与完成定义、背景、约束、参考、期望节奏。用户在快挡确认"创建长思考任务"（FR-02）。
进展摘要慢挡 → 快挡本段做了什么、当前结论、下一步计划、待决策事项（如有）。每个工作段结束或需要人决策时（FR-06）。
成果交付慢挡 → 快挡成果物清单、完成定义对照说明。慢挡判定工作收敛时（FR-06）。
决策答复快挡 → 慢挡对某个待决策事项的选择或补充信息。用户在快挡回复（FR-06）。

4 功能需求

功能按任务模块组织，覆盖 P0 全旅程。共享字段、状态与规则在第 5 章统一定义，此处引用不再重复。

FR-01

快挡会话（短思考对话面）

目的
让用户在宿主环境的现有对话流里与 AI 实时交流需求，同时对全部长思考任务保持最低限度的感知，不需要切换界面。
触发
用户在宿主（codex 或 dsh）中发起或继续对话。P0 不新建独立入口，快挡寄生在宿主已有会话中。
处理规则
  • 快挡按普通对话方式响应，负责需求澄清与追问解释。
  • 当对话内容指向一个需要持续多日推进的工作时，快挡主动提出"转交慢挡"，并进入 FR-02 简报流程；用户拒绝则继续留在快挡。
  • 快挡会话中默认只展示各长思考任务的摘要视图（名称、状态、最近进展摘要、待决策事项数），展开才看细节。
  • 长思考任务产生待决策事项时，快挡在当前会话中推送一条明确的决策请求，含问题、背景与选项（如有）。
结果与状态变化
对话记录保存在宿主会话内；被引用进简报的内容写入任务的"背景资料"字段。
例外
宿主不支持或未启用慢挡能力时，快挡仅提供普通对话，并明确告知长思考能力不可用，不静默降级。
FR-02

简报生成与确认（快 → 慢交接）

目的
把一段随意的口头需求固化为慢挡可独立执行的任务定义，保证慢挡在无人盯着时不会跑偏。
触发
快挡在对话中识别到长期工作并征得用户同意，或用户主动要求"建一个长思考任务"。
处理规则
  • 快挡从当前对话提炼简报草稿，字段与校验规则见 5.2。草稿必须回显给用户，不允许直接创建任务。
  • 用户可逐字段修改；修改后即时重显。
  • 简报中缺失"目标"或"完成定义"时禁止创建任务，快挡提示用户补充。
  • 用户确认后，简报转为任务的初始内容，任务进入"草稿→排队"转换（见 5.1）。
结果与状态变化
生成长思考任务，状态"排队"；快挡会话中出现该任务的摘要视图。
例外
用户中途放弃：草稿保留为可复用的简报草稿，不生成任务，不产生任何后台消耗。用户确认但创建失败：保留草稿并提示重试，对话不中断。
FR-03

长思考任务创建

目的
把确认后的简报变成一个有身份、有生命周期、可被追踪和干预的持久对象。
触发
用户在简报确认卡上选择"确认创建"。
处理规则
  • 创建时系统生成任务 ID，名称默认取简报目标的首句摘要。
  • 初始字段取自简报；"当前进展摘要"初始为"已创建，等待第一个工作段"。
  • 创建后任务排队等待首个工作段；调度规则见 FR-04。
  • 用户可同时持有的长思考任务数量上限 [TBD]；超出时创建被阻止并说明原因。
结果与状态变化
任务持久化，状态"排队"；快挡确认消息中显示任务名称与 ID。
例外
创建失败（存储不可用等）：保留简报草稿，提示重试，不留半个任务。
FR-04

慢挡执行（断续推进的长思考）

目的
让任务在无人监督、跨多个日历日的条件下持续向完成定义收敛，这是"长思考"区别于一次长会话的核心。
触发
任务处于"排队"且到达调度点。调度点定义 [TBD：定时 / 事件 / 会话触发的取舍见开放问题]。
处理规则
  • 执行以"工作段"为单位：一段 = 一次连续的后台推进，段与段之间可以间隔任意时长（分钟到数日）。
  • 每个工作段开始时从最新快照恢复上下文，按"下一步计划"推进；段内产出写入工作段记录。
  • 每个工作段结束时必须完成三件事：更新进展摘要、更新下一步计划、落盘快照（见 5.4）。三件事未完成不得结束工作段。
  • 遇到需要人拍板的问题时，停止继续猜测，把问题写入"待决策事项"，状态转"等待输入"。
  • 判定工作已收敛于完成定义时，进入成果交付流程（FR-06），不自行宣布完成。
  • 压缩上下文时必须保留：简报全文、完成定义、已完成事项清单、未完成事项清单（见 5.4）。
结果与状态变化
正常段结束：状态在"思考中↔排队"之间循环（断续推进）。需要人时转"等待输入"。收敛时提交成果。不可恢复错误转"失败"（见 5.8）。
例外
工作段中途宿主关闭：已落盘快照不受影响，任务下次从快照恢复，未完成的半段按"段内失败"处理（见 5.8）。同一任务不允许并发执行多个工作段。
FR-05

状态快照与恢复

目的
让"断断续续"成为产品的一等公民：任务可以停几天、换一台机器、跨宿主会话，恢复后不丢目标、不丢进度。
触发
每个工作段结束时自动触发；用户执行重试或恢复操作时触发恢复。
处理规则
  • 快照包含：简报全文、进展摘要、下一步计划、已完成与未完成事项清单、工作段记录指针。
  • 恢复时以最新快照为准；快照损坏时回退到上一个可用快照，并在工作段记录中标注回退。
  • 恢复操作本身不产生新的思考，只重建上下文，供下一工作段使用。
结果与状态变化
任务状态保持不变，"最新快照"指针更新；恢复后任务回到"排队"等待调度。
例外
无任何可用快照（任务从未开始过工作段）：恢复等于直接使用简报初始化，不报错。
FR-06

进展回流与成果交付（慢 → 快交接）

目的
用最少的注意力占用把长任务的状态同步给人：平时静默，关键时刻才打扰。
触发
工作段结束（静默更新）、产生待决策事项（主动推送）、成果收敛（主动推送）。
处理规则
  • 工作段结束：进展摘要与下一步计划写入任务，面板静默更新，不推送。
  • 待决策事项产生：向快挡会话推送决策请求，含问题、背景、选项（如有）；用户答复直接回填任务并恢复执行（见 5.1）。
  • 成果收敛：慢挡提交成果物清单与"完成定义对照"（逐条说明完成定义如何被满足），状态转"等待输入"，等待用户确认完成。
  • 用户驳回成果时必须给出原因，任务回到"排队"继续推进，已完成工作保留。
  • 用户确认完成：状态转"已完成"，任务从待办视图移入归档。
结果与状态变化
见 5.1 状态机：等待输入 ⇄ 思考中 / 排队，等待输入 → 已完成。
例外
用户长时间不答复：任务保持"等待输入"，不自动继续、不自动完成 [Assumption, TBD]；提醒节奏见 5.7。
FR-07

任务面板与人工干预

目的
让用户用一屏注意力管理全部长思考任务，并在任何时候夺回控制权。
触发
用户在快挡会话中要求查看任务，或主动唤起任务面板。
处理规则
  • 列表展示全部未归档任务：名称、状态、最近更新时间、进展摘要首行、待决策事项数。按最近更新时间倒序。
  • 支持的操作：查看详情、暂停、恢复、取消、重试、修改目标（走 5.5）。
  • 取消是不可逆操作，必须二次确认，确认文案中说明已有工作段记录会保留。
  • 修改目标必须二次确认，并展示新旧完成定义对比。
  • 面板空态：说明当前没有长思考任务，并给出"从当前对话创建"的入口。
结果与状态变化
各干预操作对应 5.1 中的合法转换；非法操作（如对"已完成"任务暂停）不显示或置灰。
例外
取消与暂停操作在工作段执行中被调用：当前工作段在最近的安全点停止并落盘快照后再执行操作，不打断落盘。

5 共享规则与例外

5.1 长思考任务状态机（唯一权威定义）

状态共 8 个：草稿排队思考中等待输入暂停已完成失败已取消

当前状态目标状态触发者触发条件
草稿排队用户确认简报并创建任务（FR-02/03）。
排队思考中系统到达调度点，启动新工作段（FR-04）。
思考中排队系统工作段正常结束，等待下一工作段——这是"断续推进"的循环。
思考中等待输入系统产生待决策事项，或提交成果等待完成确认（FR-06）。
等待输入思考中用户答复决策或驳回成果后恢复推进（FR-06）。
等待输入已完成用户确认成果满足完成定义（FR-06）。
排队 / 思考中 / 等待输入暂停用户执行暂停操作（FR-07）；暂停中的任务不参与调度。
暂停排队用户执行恢复操作（FR-07）。
排队 / 思考中 / 等待输入 / 暂停失败系统不可恢复错误或重试次数用尽（见 5.8）。
失败排队用户执行重试操作，从最近快照恢复（FR-05）。
排队 / 思考中 / 等待输入 / 暂停已取消用户二次确认后取消（FR-07），终态。

"已完成"与"已取消"为终态，不再接受任何转换，仅可归档查看。状态变化必须同时更新"最近更新时间"并写入工作段记录或操作日志。

说明："草稿"阶段的对象是简报草稿，尚未获得任务 ID；用户确认简报并创建成功后才成为正式的长思考任务并进入"排队"。被放弃的草稿不占用任务数量上限。

5.2 简报字段与校验

字段必填校验规则
目标是必须描述期望结果而非过程动作；为空禁止创建。
完成定义是必须是可逐条核对的完成条件；为空禁止创建。
背景否默认从当前会话提炼，用户可删改。
约束与边界否时间要求、禁止事项、参考范围。
期望节奏否默认值 [TBD]；仅表达优先级，不构成调度承诺。

5.3 注意力预算规则（快挡的信息呈现）

  • 默认推送且仅推送：待决策事项、成果待确认、任务失败。
  • 静默更新：工作段进展、状态在"排队↔思考中"间的循环。
  • 快挡会话中任务视图默认折叠为摘要行；展开才显示工作段记录。
  • 同一任务的未决策事项合并为一条推送，不逐条打断。

5.4 中断与续跑规则

  • 快照是恢复的唯一依据；没有落盘快照的段内进展视为未发生。
  • 压缩（compaction）允许丢弃过程细节，但简报全文、完成定义、已完成清单、未完成清单永不丢弃。
  • 恢复只重建上下文，不消耗工作段配额，不产生可见进展。

5.5 目标变更规则

  • 只有用户可以修改目标与完成定义；执行体只能在待决策事项中建议修改。
  • 修改需二次确认并展示新旧完成定义对比。
  • 目标变更后：正在进行的工作段在安全点停止、落盘快照，任务回"排队"；工作段记录保留，不作废。

5.6 权限边界

操作用户长思考执行体
创建 / 取消任务可不可
修改目标与完成定义可（需确认）仅可建议
推进工作段、写进展摘要不可直接改写，可批注可
提交成果、发起待决策事项不可代提可
确认完成 / 驳回可不可
暂停 / 恢复 / 重试可不可

5.7 通知时机

事件是否推送去向
任务创建成功推送一次当前快挡会话
待决策事项产生推送当前快挡会话，合并同类
成果待确认推送当前快挡会话
任务失败推送当前快挡会话
工作段进展不推送仅更新任务面板
等待输入超时提醒提醒频率 [TBD]当前快挡会话

5.8 异常与恢复

场景处理规则
宿主进程关闭 / 离线任务与快照已持久化，状态不变；执行体不运行期间不消耗资源；用户下次进入时任务原样可见。
工作段中途失败回退到最近快照，自动重试一次 [Assumption, TBD]；再失败转"失败"并推送用户。
上下文超限触发压缩与笔记沉淀，按 5.4 保留不可丢弃内容；压缩不改变任务状态。
用户长期不响应任务保持"等待输入"，不自动继续、不自动完成；按 5.7 提醒。
取消后已产生的中间产出工作段记录与中间产出保留可查阅，不自动删除、不自动外发 [Assumption, TBD]。
同一任务被并发调度禁止；后到的调度请求丢弃并记入工作段记录。

7 术语表

术语定义
快挡（短思考）与人实时对话的思考轨道，秒级响应，会话内连续，占用人的注意力。
慢挡（长思考）后台推进任务的思考轨道，工作段制，跨日历日断续运行，不要求人在线。
简报快挡交给慢挡的任务定义，含目标、完成定义、背景、约束。
工作段慢挡一次连续的后台推进，是长思考的基本执行单位。
快照工作段结束时落盘的完整任务状态，是中断恢复的唯一依据。
进展摘要慢挡每工作段产出的面向人的进度说明。
待决策事项慢挡提请人拍板的问题，是快挡默认推送的唯一内容类型。
注意力预算用户能分配给"监工 AI"的固定注意力额度，是快挡信息呈现规则的设计依据。
